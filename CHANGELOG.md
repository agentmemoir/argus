# Changelog

Notable changes to this project are documented here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/). This project intends to follow [Semantic Versioning](https://semver.org/spec/v2.0.0.html); no version has been released yet.

## [Unreleased]

- The readiness report reads the crontab, read only, and says whether a line runs the configuration. When none does, it prints the exact line to install and the check that proves it worked. Argus never edits a crontab. ([#216](https://github.com/agentmemoir/argus/issues/216))

- A board whose remote holds no claims branch reads as an empty board. The first claim write creates the branch, through the existing write path. A remote that cannot be asked still fails closed. ([#216](https://github.com/agentmemoir/argus/issues/216))

- The run-state folder and the driver's state folder inside it are made when they are missing, and the driver says so in one line for each. A folder that Argus does not own, such as a board or phases checkout, is still not made. ([#216](https://github.com/agentmemoir/argus/issues/216))

- A configuration with a `board` object defaults `driver.runs` to a `runs` folder inside the board checkout, and it refuses a run folder set outside that checkout, naming the key. ([#216](https://github.com/agentmemoir/argus/issues/216))

- Argus runs each Glide stage with TMPDIR and BUN_TMPDIR set to a stage folder under the run state, so a host whose default temporary folder is mounted noexec does not need them set by hand. `--check` creates that folder and runs a file in it, and it names the cause and the action when the folder refuses to run files. ([#216](https://github.com/agentmemoir/argus/issues/216))

- The CI repair step reads the checks of each open driver pull request on every tick, also while a phase window runs; a repair round still waits for the window. A failed checks read, head read, or pull request listing now ends the tick before new work. A check that stays pending for more than 30 minutes on one head sends one Needs You notice for that head, and the notice clears when no check is pending. ([#197](https://github.com/agentmemoir/argus/issues/197))

- The example issue pipeline's post_step hook now runs an example script that exists. It exits non-zero when the checkpoint or open-pr mode refuses, so the step stays incomplete. The open-pr refusal for --branch, --repo, or --phase names the flag and says it does not apply. ([#209](https://github.com/agentmemoir/argus/issues/209))

- The ready sweep reads each pull request once per pass. A group has one pull request shared by every member, so the sweep used to read its timeline and checks once per member. The first answer is now kept by pull request URL for the rest of that pass, and a pull request readied in the pass is not readied again. Merged, closed, or already readied pull requests are still read on later passes. ([#181](https://github.com/agentmemoir/argus/issues/181))

- Docs: the repair section now states that a pull request that was escalated gets no further repair round or notice, even when its checks turn red again, and that an unreadable attempt record sends one notice and starts no round. ([#210](https://github.com/agentmemoir/argus/issues/210))

- A repair attempt record that cannot be read now sends one Needs You notice that names the record file and says no repair round starts. Before, the driver logged the checks as unreadable on every tick and sent no notice. ([#210](https://github.com/agentmemoir/argus/issues/210))

- The repair task file puts the failed-job log tail in a code fence longer than any run of backticks in the log, so a log line cannot close the fence early and turn the rest of the log into task text. ([#210](https://github.com/agentmemoir/argus/issues/210))

- The issue open-pr path re-reads its claim just before it creates the draft pull request, so a claim lost during the list read creates nothing. With `--kind issue --mode open-pr`, `--branch`, `--repo`, and `--phase` are refused by name, because the branch comes from the claim. The example issue stage names the open-pr command. ([#209](https://github.com/agentmemoir/argus/issues/209))

- The resync step no longer merges the integration branch into the board checkout, which holds claims and is not a work checkout. A board on its claims branch is named as a skipped no-op. A merge that git refuses, such as one between unrelated histories, now reports as blocked, not continued. ([#219](https://github.com/agentmemoir/argus/issues/219))

- Issue pull requests are marked ready for review once every check on them passes. The ready sweep reuses the group ready transition, with its once-only guard, and skips a pull request while its issue run or a repair round runs. ([#198](https://github.com/agentmemoir/argus/issues/198))

- `argus --check` now runs the pipeline's `pre_run` hook once, from the repository root, as Glide does. A refusing hook fails the check with its first line and one action, so a bad setup shows before the first tick. The check runs the hook for real, so a `pre_run` hook must be read-only. ([#220](https://github.com/agentmemoir/argus/issues/220))

- The check read of a pull request now names the repository it reads. The peek-ci mode and the CI repair step take the owner, repo, and host from the pull request URL. A read with no owner or no repo is refused, and gh is not run. A bare pull request number gets no check read in those two steps, so its result says the repository is missing. ([#180](https://github.com/agentmemoir/argus/issues/180))

- A `failed.json` left by a glide stop before `run.json` was written is cleared before the next run starts in that folder. It no longer stays beside the new run, where the selector read it as a failed phase. ([#214](https://github.com/agentmemoir/argus/issues/214))

- Docs: the issue driver pages now state the trust rules, claim label, branch names, and launch-fault retries as the code runs them. A new page gives the setup steps for an issue driver host, and the known gaps are listed in the issue page.

- A run-state commit or push that fails no longer reads as a clean sync. The sync summary says `DEGRADED` and names the failed step, and the driver log says the run state did not land. The result gives git's step and exit code, not git's error text, so no machine name reaches output or the run folder. The phase reservation file is written by a JSON encoder, so an id with a quote still makes valid JSON. ([#174](https://github.com/agentmemoir/argus/issues/174), [#175](https://github.com/agentmemoir/argus/issues/175), [#178](https://github.com/agentmemoir/argus/issues/178))

- When `gitsync --mode branch` crashes for a phase and writes no result, Argus no longer launches the phase on the current branch. The tick refuses the launch, keeps the claim, and sends one Needs You notice for that phase. The next tick retries the cut.

- The timeline read from gh closes stdin, so gh cannot wait on the driver's terminal, and decodes its output as UTF-8 on every host. ([#179](https://github.com/agentmemoir/argus/issues/179))

- The ready sweep sends the timeline read's owner and repository name to gh as strings, so an all-digit name no longer fails GraphQL and blocks a ready pull request. ([#176](https://github.com/agentmemoir/argus/issues/176))

- Issue task files, and so issue branch names, use only the first three words of the issue title, for example `issue/266-backup-restore-refuses`. An issue already in progress keeps the branch recorded in its frozen task snapshot, so resume and publish do not rename it.

- An issue run whose `pre_run` hook refuses it (glide records `config_error` at hook point `pre_run`), or whose issue branch cannot be cut, is a launch fault. Any other glide failure, including rc=2 inside a stage, keeps the failed-run path. The driver keeps the claim, renews it while halted, and halts the line, so no tick takes another issue. A claim given back by any path ends the fault. Later ticks retry the same issue after 10 minutes, then every 20 minutes. A run that starts clears the halt with no hand step. After the third failed attempt, one Needs You names the cause, the action, and the check. The issue clean sweep skips a run folder that has no reservation file.

- When Argus cannot put an issue on its own branch, it no longer launches the run on the base branch. It keeps the board claim and halts as a launch fault (see the launch-fault entry above). A phase keeps the old repair path. In issues mode, the phases folder reads as empty instead of failing on an unset `PHASES_DIRECTORY`. ([#215](https://github.com/agentmemoir/argus/issues/215), [#218](https://github.com/agentmemoir/argus/issues/218))

- A failed or escalated issue run now gives its board claim back and keeps the claim label. Its Needs You notice says: remove the label from issue #N to let Argus retry. While the label is there and no board record holds the issue, it is skipped; once a person removes the label, a later tick can pick the issue again. If the release fails, the notice says the claim could not be given back, and the issue is picked again after the claim expires and its cooldown passes, even with the label. Completed, rejected, and accepted issues stay blocked. ([#203](https://github.com/agentmemoir/argus/issues/203))

- `gitsync --mode open-pr` and `--mode peek-ci` use a pull request for the branch only when its head branch is in this repository and has the same name. A row with a missing value is not used.
- The running guide says two drivers must not share one checkout, and how to give each its own clone, run folder, state folder, and tmux session. The issues guide says the default `trusted-associations` trusts an organization member on the next read, and how to drop `MEMBER`. ([#199](https://github.com/agentmemoir/argus/issues/199), [#200](https://github.com/agentmemoir/argus/issues/200))

- A tick starts a CI repair round before new work when a phase pull request that waits on review, or an open pull request on a branch an issue run folder records, has a failed check. A fork pull request with the same branch name as an issue branch is ignored. The round runs `repair.pipeline` in the phase window, inside its own temporary git worktree on the pull request branch, so the main checkout never moves. The session pushes the run's commit to that branch without force and removes the worktree; the next tick removes a worktree a crash left behind. Before a removal, work that was not pushed, a push the remote refused included, is kept on a `refs/argus/repair-backup/<pr>-<time>` ref that a notice names. A round counts only after its launch, and after `repair.attempts` rounds a still-red check sends one notice. The round's `glide` gets `ARGUS_CONFIG_FILE`. ([#196](https://github.com/agentmemoir/argus/issues/196))

- The configuration accepts `repair.pipeline`, `repair.attempts`, and `repair.wait` for the CI repair round, and passes them to the driver as `REPAIR_*` variables. With no `repair` object, the defaults are `repair.yaml` beside `pipeline`, 3 attempts, and 600 seconds. A `repair` object no longer warns as stale. ([#195](https://github.com/agentmemoir/argus/issues/195))

- When Argus claims an issue, it adds the claim label to the issue on GitHub after the trust check. It creates the label once when the repository lacks it and logs that. A failed label write keeps the claim. Argus never removes the label. ([#184](https://github.com/agentmemoir/argus/issues/184))

- Issue selection skips an open issue that carries the claim label, set by `issues.claim-label` with the default `accepted`. A person can keep an issue by adding the label. A held or expired board claim still decides for its own issue. The skip counters gain `claim_label`. ([#186](https://github.com/agentmemoir/argus/issues/186))

- The example issue pipeline is one step with a `post_step` hook that runs the issue checkpoint, then open-pr. The step does the fix, its review, and its publication. `glide run --dry-run` validates it. ([#193](https://github.com/agentmemoir/argus/issues/193), [#194](https://github.com/agentmemoir/argus/issues/194))

- `gitsync --kind issue --mode open-pr` opens or reuses the draft pull request for the checked-out issue branch through the same open-pr mode as a phase, so the draft state is read back after the create. It first proves this worker still holds the issue claim, and it refuses a checked-out branch that is not the one the claim recorded. On a branch that is not an issue branch it reports a warning and opens nothing. The issue checkpoint now commits as `wip: work in progress on <branch>`, and it no longer fails to stage when an ignore rule already keeps the private checkout out. ([#191](https://github.com/agentmemoir/argus/issues/191), [#192](https://github.com/agentmemoir/argus/issues/192))

- A tick that cannot save or prove its selected claim returns that reservation to the queue. It keeps another machine's replacement claim and records a refused cleanup. ([#183](https://github.com/agentmemoir/argus/issues/183))

- Release repairs a missing or stale phase reservation from its proved claim before saving partial work. It keeps the claim when that file cannot be saved. Issue claims leave phase reservation files unchanged. ([#183](https://github.com/agentmemoir/argus/issues/183))

- Phase write fences and publication use the local machine identity when reading a saved reservation. A copied reservation from another machine cannot grant ownership or let clean land its live run state. ([#183](https://github.com/agentmemoir/argus/issues/183))

- Single-phase and whole-tree `gitsync --mode clean` land a phase's run state when its reservation file is missing and the board shows no live claim. A published receipt also needs that board proof when the reservation is missing. A live claim, an unavailable board, or a malformed or unreadable reservation file still blocks that recovery. ([#173](https://github.com/agentmemoir/argus/issues/173))

- CI runs the whole test suite in the affected-checks job, so a test in any file can fail the build. A guard test fails if the workflow narrows back to a hand-written file list that misses a test file. ([#170](https://github.com/agentmemoir/argus/issues/170))

- A resume stops with no launch when the board fence refuses the branch cut, and the resume now cuts the branch after it renews or takes its fence and records its claim. A group declaration the resume cannot read is still refused before the fence, so that refusal takes no reservation. Every other branch failure is still a repair.

- `abandon` and `resume` are tested against a real local board and the real `assert_owner` fence. Under another machine's live claim, each refuses and leaves the claim and the board unchanged; under this machine's fence, abandon parks the phase and resume passes the fence check.

- `argus abandon` writes the residue to `abandoned.json.pending`, then releases the board group, then renames it to `abandoned.json`. A failed residue write stops the command with the claim held and nothing released, so the same command can run again. A failed release stops the command and parks nothing. A failed rename after the release reports failure and keeps the staged file. ([#164](https://github.com/agentmemoir/argus/issues/164))

- `argus abandon` parks a phase when no other machine holds a live claim on its group. When this machine still holds the claim, it releases the group first. When no machine holds a live claim (no claim, an expired claim, or a terminal record), it parks with no release, because nothing is held. It refuses when another machine holds a live claim on the group, or when the board cannot answer, and it writes nothing. A rerun of the same command on a halted phase finishes a park whose rename failed. ([#171](https://github.com/agentmemoir/argus/issues/171))

- A whole-tree `gitsync --mode clean` that skips every phase now reports not ok and exits 1. A sweep that lands at least one phase still succeeds, and its summary names each skipped phase with its phase number, state, and reason. ([#164](https://github.com/agentmemoir/argus/issues/164))

- The tick stops with no launch when `gitsync --mode branch` refuses on the phase fence (FENCED or COORDINATION_UNAVAILABLE), instead of launching on the branch the checkout already has. Every other branch failure is still a repair. ([#164](https://github.com/agentmemoir/argus/issues/164))

- The driver writes the phase reservation file the write fences read, from the same board-confirmed claim it records in the shell claim file.

- The group gate's check read names the pull request's own repository and host on the `gh` call: `gh pr checks` now receives `--repo [HOST/]OWNER/REPO` from the receipt's `owner`, `repo`, and `host`, the same triple the stage-history read already used. Without it gh answered about the repository of the run directory, so a run directory outside a checkout, or on a different repository, read another repository's checks and reported them as this group's. ([#168](https://github.com/agentmemoir/argus/pull/168))

- `--release` drops the driver lock on every return path, the board's refusal included. That one path kept fd 9 open and with it the flock, so the operator's next driver command in the same shell was refused by a lock nothing else held. The operator commands (`stop`, `release`, and the phase-window wait they share) move to `lib-driver-control.sh`, one file per responsibility, and the tick file stays under the executable size limit. ([#168](https://github.com/agentmemoir/argus/pull/168))

- The board fence is bounded on a host with neither `timeout` nor `gtimeout`. The assert-owner call runs in the background, its pid is polled every 0.2s without a busy spin, and it is sent SIGTERM then SIGKILL after `ARGUS_FENCE_TIMEOUT_S` seconds (20 by default, the value the timer path always used). A timeout is a refusal, exactly as a timer's kill is, so a hung board can no longer hold the driver lock for ever. ([#168](https://github.com/agentmemoir/argus/pull/168))

- A reservation group's shared draft pull request is readied by a later tick, not only by the publish that completes the group. The new `gitsync --mode ready` sweep runs in the driver's maintenance pass, never in issues mode, and sweeps every phase receipt to retry the ready, so a group whose checks were still running when it published is readied once they pass instead of staying in draft for ever. It runs for a receipt that already reads `published`, which the old per-phase retry could not reach: `--mode published` only runs for a phase waiting on a merge, and the receipt settles on that same tick. ([#166](https://github.com/agentmemoir/argus/issues/166))

- The ready sweep writes no phase state, holds no claim, and never changes a published or merge verdict. The transition is once per pull request and GitHub's own ready/draft timeline is the guard: any ready event skips the retry, so a person who re-drafts the pull request is never overridden, and a pending or empty check report takes no transition.

- Phase state and publication writes read the board fence before they write. `gitsync --mode published` verifies the phase's reservation with `assert_owner` before the receipt is marked published and returns `FENCED` on a mismatch; `--release` proves the fence before the checkpoint push and the group release; `abandon` proves the fence before the residue is written; and `record_claim` refuses a pair the board does not confirm as a live claim. A board that cannot answer fails closed on every path. ([#164](https://github.com/agentmemoir/argus/issues/164))

- `argus --stop` always writes the local halt marker, so a stop holds this machine's line whether or not a fence holds. Only the manual-stop hold (`stopped-claim`) is fenced: `--stop` takes the driver lock, reads the claim, and asks the board with `assert_owner` before it writes that hold, and a bad, empty, unreadable, or mismatched fence writes no `stopped-claim`. ([#164](https://github.com/agentmemoir/argus/issues/164))

- `gitsync --mode tidy` accepts `--phase` and proves the fence before it moves a checkout, and `--mode branch` proves it before the branch cut. The pre-selection tidy call has no phase to name, so it stays unfenced and keeps its dirty-tree refusal; only the branch cut's call, which knows the phase, passes it. ([#164](https://github.com/agentmemoir/argus/issues/164))

- `gitsync --mode clean`, single phase or sweep, lands a phase's run state unless another machine holds a live claim on its group or the board cannot answer, and a record that is rejected, completed, accepted, released, or expired lands too, as does a claim whose window has passed and this machine's own live claim. The fence is proved before the run-state commit and push. `--mode checkpoint` proves it before it stages or commits. The fresh-start sweep that runs with no phase decides per planned phase: a refused phase is skipped, and the result names it with its phase number and reason. A sweep that skips every phase now fails; a sweep that lands at least one phase still succeeds. ([#164](https://github.com/agentmemoir/argus/issues/164))

- Every one of those fences returns `FENCED` on a mismatch and `COORDINATION_UNAVAILABLE` when the reservation cannot be read or the board cannot answer, through the one helper `argus.gitsync.fence.phase_fence`, and every refusal writes nothing. ([#164](https://github.com/agentmemoir/argus/issues/164))

- The last member of a reservation group makes the shared draft pull request ready for review. The publish step readies the shared pull request once every member has published and the pull request's checks all pass; the once-guard is GitHub's own ready/draft timeline, so a rerun, or a later tick, never overrides a human who re-drafted the pull request. ([#166](https://github.com/agentmemoir/argus/issues/166))

- The ready-once record beside the receipt is deleted, with its writer, its reader, the `persist_attempt` parameter, and the run-state commit that wrote it. No production writer ever emitted the version the reader accepted, the version-2 attempt it did write was discarded unread, and the timeline already answers the question, so the record could only refuse a ready a later tick should have taken. The GitHub ready/draft timeline is the guard and is named as such in the docs. ([#166](https://github.com/agentmemoir/argus/issues/166))

- The ready sweep runs on a real run directory and a fake `gh` on `PATH` that records the transition it was asked for, `gh pr checks` is asserted on the full argv and a non-default host, `abandon`'s ordering runs the real shell function against a board release that fails and one that succeeds, and each fenced write path has a negative and a positive case that asserts the file, ref, and board are unchanged.

- The ready sweep logs `a group's shared pull request is ready; its checks passed` only on the tick that readies a pull request. A pull request that an earlier tick readied is skipped, and its result still reads `READY`, so that line is no longer repeated for it on every tick.

- `gitsync --mode open-pr` refuses to create a draft pull request without `--body-file`, so a draft is never opened with an empty body that could be published before a later pass filled it; reusing an open pull request needs no body file, and the title still defaults to the branch name. ([#167](https://github.com/agentmemoir/argus/issues/167))

- `python -m argus.board.reservations scan` reports each phase whose run directory holds `run.json`, `resume.json`, or a `session-*.log` but whose claim is missing, expired, held by another machine, or terminal. It is a read-only board read that writes nothing, takes optional `--phase` and `--machine-id`, and exits 2 when the board is unreadable.

- `--session` runs one phase only under a live claim, or not at all. A pane a tick opened has the fence it was given verified against the board before the work starts; a session started by hand resolves the phase's declared group and claims it, or reserves the phase alone, and refuses with one actionable line on a conflict, a cooldown, a stale fence, or an unreachable board. The run is written to the claim file, so `--release`, `--stop`, `abandon`, and `--resume` read it unchanged, and the claim is marked `running` immediately before the launch. An empty machine id is refused. ([#163](https://github.com/agentmemoir/argus/issues/163))

- The phase pipeline can open or reuse its draft pull request and read its check state again, through two gitsync modes. `open-pr` creates a draft for the phase's branch, reuses the one already open for it, and answers `state: blocked` naming the pull request when the newest one for that branch is merged or closed; a pull request list that cannot be read stops the mode rather than reading as none, so a network blip cannot open a second draft. `peek-ci`, removed with no shim in #156, returns as one non-waiting read of the branch's checks: `ok` is true only when gh reported at least one row and every row's bucket is `pass`, because a skipped, neutral, or cancelled check leaves gh's exit code 0 and an empty list is not a pass, and the summary says what ran, what did not, and what is unknown. The pipeline's post-step helper still records this result and exits 0, so a blocked `open-pr` is a note in the record and never a failed step. ([#161](https://github.com/agentmemoir/argus/pull/161))

- A terminal retry keeps an owner-edited `harnesses.json`: the `--fresh` restart archives the run directory, glide restores the edited map into the new one and fills only the missing fields (glide #66), and the driver logs the detected owner edit before the restart, naming the file and the run. The estimate reader keys the developer factor on the saved `steps.developer.harness` alone, so a harness-only edit changes the factor key, and an unreadable map is a skipped update, never a stop. Argus never chooses a harness. ([#159](https://github.com/agentmemoir/argus/pull/159))

- Argus no longer proves the glide ledger or auto-pins its step commits on resume. Completion proof lives in glide's ledger; a resume gate that met a terminal or moved run, or a damaged run result, logs the reason and continues on the phase's own branch for glide to repair. ([#157](https://github.com/agentmemoir/argus/pull/157))

- Argus reads glide's atomic `result.json` for every state. A `repair_pending` result is a resumable no-launch tick: the driver logs the step and the reason, writes no halt, and neither archives nor finalizes the run; the next tick continues it. ([#157](https://github.com/agentmemoir/argus/pull/157))

- A plan's open decision gate no longer stops the line. `BLOCKED_ON_GATE` is gone from the selector, the driver, and `next_phase.py` `STATE_EXIT`; the gate is reported under `needs_decision` and every later phase still gets its turn. ([#157](https://github.com/agentmemoir/argus/pull/157))

- Branch, merge, sync, run-state, and publication failures that do not threaten work on disk now report and continue instead of halting. A clean checkout on any other branch is switched to the phase branch; a dirty tree is the narrow lost-work stop. Run-state commits are scoped with `git commit -- <pathspec>`, so a staged path from another phase cannot ride them. A blocked tidy preserves the phase's own work with a scoped commit and continues, and keeps a narrow stop only when the work cannot be preserved. ([#157](https://github.com/agentmemoir/argus/pull/157))

- Publication checks the configured Git destinations before it commits or pushes: a shared destination returns `RETRY` with no push and no receipt. No receipt is written unless a pushed head is recorded for both checkouts and a pull request is recorded, and a receipt is marked published only under the same condition; a missing head or a missing pull request leaves the phase waiting. ([#157](https://github.com/agentmemoir/argus/pull/157))

- A stale config key (`roadmap-dir`, `phases-dir`, `repair`) and an unknown key, nested ones included, warn once with the exact replacement and continue. An unacceptable value still stops and names the fix. ([#157](https://github.com/agentmemoir/argus/pull/157))

- A new stop path in the driver or gitsync fails the build. The tripwire scans every shell and Python stop form and allows only the stops with an owner reason, keyed by file, rule, owner function, and the occurrence of that form, so a new function and a second stop of the same form in an already-allowed function both fail. ([#157](https://github.com/agentmemoir/argus/pull/157))

- A failed glide job is retried with capped full jitter and, when the retries run out, recorded as `failed.json` beside the run directory; the selector skips that phase and the line continues to the next job instead of halting until a person clears it. The retry count is `ARGUS_JOB_RETRIES`, 3 retries (4 attempts) by default. ([#156](https://github.com/agentmemoir/argus/pull/156))

- The publication path no longer blocks on git history, merge-base, tree, commit-id, or receipt gates, and a tick no longer runs the GitHub group gate, the repair loop, or the pull-request lifecycle reads; commit, push, and opening the pull request stay. ([#156](https://github.com/agentmemoir/argus/pull/156))

- The outbound secret scan now replaces each secret-looking span in a reply with `[redacted]` and posts the reply, instead of refusing it. ([#156](https://github.com/agentmemoir/argus/pull/156))

- Removed with no shim: the board `--self-test` flag (the `self-test` subcommand is the only spelling), the `DISABLE_DISCORD` environment alias (use `DISABLE_NOTIFY`), the `roadmap-dir` and `phases-dir` top-level config keys (use the `phases` object; both are refused by name), the `--repair-session` flag, and the gitsync `peek-ci` mode. The `issues.announce` and `issues.pr-check-max` config keys and the `watching` key in the issue selection output go with the removed halt and pull-request reads. ([#156](https://github.com/agentmemoir/argus/pull/156))

- GitHub issue work is restored: `driver.provider: issues` selects from a backlog and claims on the shared board, with the failure halt marker, the `--add-assignee` announce, and the closure read stripped, so only Argus's own reservation, running job, or state stops the run and a published issue returns `AWAITING_REVIEW`. A failed issue job now advances the line to another issue while its claim waits to resume through the claim windows. The outbound secret scan returns on the reply path, where it redacts rather than refuses. ([#156](https://github.com/agentmemoir/argus/pull/156))

- `--clear-halt` (`make clear-halt`) removes the halt and stall markers, and the halt record `halted.json` with them only when the phase it names has neither `run.json` nor `resume.json`, so a halt that came before the phase ever started can be cleared instead of needing a hand `rm`; a resumable phase keeps its record and the command says why, and a record that cannot be read is kept too. The command prints each path it removed and removes no run directory, log, or reservation.

- A halt names the state and the reason glide left behind when there is no run result to read. Only when `run.json` is absent does the driver read the trailing JSON object from `session-<phase>.log`, and only from the part this launch appended, so a payload from an earlier launch cannot stand in for it; the object's `state` goes into the halt marker, the driver log line, and the halt record, and its `error` goes in the record's reason, flattened to one line and length-capped. A damaged or unreadable `run.json`, or a log with no payload from this launch, keeps the previous `state=unknown` answer and the resume gate's refusal, and the exit-code handling is unchanged. ([#136](https://github.com/agentmemoir/argus/issues/136))

- `show` takes two filters, so a reader can ask for one reservation or one machine instead of the whole board. `--reservation-id` narrows the phase records to that reservation, and repeats for more than one; `--machine-id` narrows the phase records and the live publication lock to one machine, and drops the `publication` key when the lock belongs to another machine, so a lock this machine does not hold is not reported as its own. An id the board does not hold is absent from the answer rather than an error, spacing around a value is ignored, and an empty identifier is refused before the board is read. ([#132](https://github.com/agentmemoir/argus/pull/132))

- A repair session that outlives its wall time is now named instead of leaving the line silently stopped. The `repair` object takes an optional `repair.stale-after`, in seconds, and 0 means no watch: the launch writes `repair-<id>.start` in the state folder and the session removes it when it ends, so a tick that finds the window alive with that record at or past the limit logs one line naming the id, the age and the limit, and sends one notice per session; nothing is killed. `--self-test` also takes an optional group name, so `python -m argus.gitsync.main --self-test repair` runs the repair step and its scan alone, the bare flag still runs every group, and an unknown name is refused with the accepted group named.

- A repair round now checks the scope it changed before the next attempt is counted. The `repair` object takes two optional keys: `repair.verify` is a command run from `repo-root` after a repair pushes, given the paths that repair changed in `ARGUS_REPAIR_CHANGED`, one per line, and the commit it started from in `ARGUS_REPAIR_BASE`, and `repair.verify-timeout` bounds how long it may run, applied with `timeout`, or with `gtimeout` where `timeout` is not on PATH; with neither on PATH the command runs unbounded and the driver logs one line saying so. A round writes `verify.id`, its own marker, beside `verify.paths` and `verify.command` before it pushes, and `verify.log` and `verify.rc` after the command runs; an answer whose `verify.id` names another round is ignored, a marker with no `verify.rc` yet reads as running, and a push that fails or pushes nothing clears those five files, so that round is counted as before. A round is a folder named `<pr>-<round>`, and the budget counts attempts: the task header names both numbers, as in `Attempt: 2 of 3 (round 5)`. A round whose own scope fails does not spend an attempt, so the budget stays open for the failure the round was given; the driver logs it as a self-introduced regression, the next task carries the check's output and the paths it covered, and the number of rounds is capped at twice `repair.attempts`, so a repair that keeps regressing still ends in `EXHAUSTED`.

- The driver self-test owns its tmux server: it drops `TMUX` and `TMUX_PANE` before any tmux command, and the leftover sweep unsets them as well, because tmux prefers the server named in `TMUX` over the socket directory it is pointed at. Run from inside a terminal's tmux, the suite used to list and kill sessions on that terminal's server, and the sweep's `kill-server` path ended it, taking every session on it down.

- The driver self-test bounds git discovery at its fixture tree, so a fixture that has lost its own repository refuses instead of walking up into the checkout under test; the fault harness bounds its scratch space the same way. Two cases pin it without assuming a layout: `git_ceiling` proves anything is there to walk to (the path resolves upward with the ceiling off), asserts the refusal, and starts a throwaway tmux session from its environment to check the server's global environment, which the tick's panes inherit; `lost_repo` re-runs the original trigger end to end — a fixture whose `.git` is removed, the real tick in tmux — and asserts the refusal is the first git step's and the enclosing checkout is untouched. Outside that layout the cases say they skipped instead of claiming a bound that never bound. ([#116](https://github.com/agentmemoir/argus/issues/116))

- The repair step reads a pull request's code-scanning alerts when a failing check has no workflow run to open. A code-scanning check's link is a scan result, so `gh run view` can read no log for it, and the repair used to stop there with `BLOCKED`. The alerts are now a second kind of evidence: the task carries them in their own section, the whole list is kept beside the task, a long list is cut where the cut can be seen, the read is pinned to the pull request's head, and a read that fails is named for itself instead of reading as an empty alert list.

- The README is now a landing page that links into `docs/` instead of restating it, and the `docs/` set names every configuration key, the package-root program files, and every run mode, including `--merge-check-only` and `abandon`.

- The `verify` workflow sets `permissions: contents: read`, so its jobs run with a read-only `GITHUB_TOKEN` instead of the repository default.

- A pull request signal snapshot and its events name the comment-trust boolean `allowed` instead of `trusted`, and the `Visibility` field, the fetch parameter, and the reply check follow the new name. The old name is also a static-analysis pattern for sensitive data, so it raised a false code-scanning alert on the signal print.

- The `roadmap` work source is now `phases`. A `phases` object names a checkout, a folder inside it, a branch and a remote; Argus commits and pushes its writes under that folder there, on the same fresh-fetch, retry-and-fail-closed transaction the board uses. The public repo-root must use a different Git push/fetch destination from the private board and phases checkouts, which may share one. The old `roadmap-dir` key is replaced by `phases.directory`.

- A self-test run killed with SIGKILL no longer leaves its tmux session, the idle monitor inside it, and its fixture directory behind. The monitor now ends a session the self-test made as soon as the run that owns it is gone, which closes the session's windows with it, and the fixture directory is recovered by the next run: each run records its own pid and the socket directory of the server it starts in `<fixture>/owner`, and the next run stops the sessions whose name ends in that pid, stops the server whose socket sits inside the fixture, and removes the fixture. A fixture whose recorded run is still alive is left alone, so two runs on one machine cannot delete each other's; a fixture is left in place rather than removed when tmux cannot be asked whether its sessions are gone; a record that cannot be read is swept on age instead of stopping the whole run; and a fixture with no record keeps the hour-old age rule. A fixture kept on purpose with `SELFTEST_KEEP_TMP=1` drops its record, so the next run no longer reads it as abandoned, and the age rule reclaims it about an hour later. The sweep asks `argus/exec_tempdir.py` which directories a fixture can be in, so it looks in the default temporary directory as well: it named `/tmp` alone before, and on macOS that is not where a fixture goes.

- The sync self-test and the fault harness remove their scratch directories instead of leaving them behind, and every scratch directory now carries the pid of the process that made it, so a run killed before its cleanup is reclaimed by the next run rather than waiting for the hour-old age rule.

- The readiness report's two self-tests run git with a fixed configuration (`GIT_CONFIG_GLOBAL` at `/dev/null` and `GIT_CONFIG_NOSYSTEM=1`), so a host's global `core.hooksPath`, signing key, template, or alias no longer reaches their fixture repositories. A machine-wide hook started its hooks inside every fixture git call, which made `make example-check` and `make install-check` several times slower, and a hook that fails made both self-tests fail for a reason that was not in Argus. A repository-local `core.hooksPath` still wins, which is what the rejected-push check installs, and a real run's git calls keep the machine's configuration.

- Estimate factor: with an `estimate` object in the configuration, a phase that finishes from a fresh start moves its developer harness's factor toward phase hours / (ideal days × 2), at most 20% per phase, and the driver commits and pushes the factor file alone. A resumed run is skipped, a harness with no factor starts from the slowest one, and a failed commit puts the file back.

- `make self-test` and `make guard-faults` refuse to start unless the `CI` variable is set; `ARGUS_ALLOW_LOCAL=1` overrides. `make quick` runs the lint, format, type, line-limit, and prose checks without tests.

- Phase helpers can open a draft after the first commit, stage checkpoint paths, and record one CI read. The driver retries readiness for lone and grouped phases.

- `--merge-check-only` settles phase publication and group readiness without selecting, reserving, or launching work. Halted ticks do the same maintenance once no phase process is active. A tick that records a merge or makes a group ready ends before selecting new work. `--stop` holds its claim for an explicit `--resume` or `--release`; clearing the halt marker alone cannot restart it. A resume keeps the line's halt marker.
- `argus` watches a phase's pull request on each tick: code-scanning alerts and review comments are recorded as they change, and one scoped command replies to or reacts to a recorded review comment.
- `argus` ticks an unattended work queue: select a phase, reserve it on a shared Git board, launch its pipeline in tmux, watch the run, and check publication before the next tick.
- One JSONC configuration file names every path and command; a missing required key stops the tick and names the key.
- Reservation groups: several phases claimed in one board write, run on one branch, and published under one pull request, with the claim renewed while a member runs.
- Halt markers on blocked or failed runs, claim cooldown and expiry handling, and a remedy escalation that records open findings and releases the claim.
- Modes: `--check`, `--dry-run`, `--self-test`, `--stop`, and `--session <NUMBER> <PHASE-FILE>`.
- Checks: the driver self-test, the guard-faults harness, and a wheel that ships the shell driver.

- A relative `--repo-root` or `--phases-directory` resolves against the working directory, not the configuration file's folder, so `--root .` from the project root names the project root.
- The tmux idle watcher ends when the process that started it is gone, so one run outside tmux, or after its tmux server died, no longer loops as an orphan.
- A reservation group's pull request is made ready for review only when every member has published and its checks pass; a pull request with failing, running, or unreported checks stays in draft with the reason in the publication output, and the driver readies it on the first tick that finds the checks green.
- Publishing a group member merges the open pull requests that target the group branch when they are ready, from this repository, mergeable, not blocked by a review, and green, so a fix for a bug an earlier member left lands before the next member starts. The new `--mode gate --phase NUMBER` runs the same step by hand.

- Notices go to the `notify.channel` target as written. The driver put `discord:` in front of it a second time, so a channel written as the sample shows (`discord:<id>`) was never delivered.
- The publication output no longer warns that a group member's branch was cut from the earlier member of the same group.
- Self-healing: with a `repair` object in the configuration, a tick that finds the checks of a pull request it published finished red starts one repair run on that branch, at most `repair.attempts` times per pull request. While the checks of a published pull request are still running, the tick waits up to `repair.wait` seconds before starting other work. A repair run never halts the line. `--mode repair` prints the plan.
- A tick that finds the queue empty now runs the merge check on the pull requests still waiting for review. It used to refuse with "coordination state unavailable" on every tick, because it read the selector's exit code, where 1 means nothing is left to reserve, and the last pull requests of a queue were never recorded as merged. The driver now judges whether the selector printed a state, so a selector that gave none still refuses, and a queue waiting on a decision (`BLOCKED_ON_GATE`) is reported as waiting. The selection asked again after the merge check is judged the same way, so the tick that records the last merged pull request of a queue no longer ends in a refusal.
- A line that repeats from tick to tick (the configuration, a renewed claim, a waiting pull request, the selector's warnings, an empty queue, a halt) is logged when it changes, not on every tick. The log is still touched on each tick.

- A halt is recoverable.
