# Changelog

Notable changes to this project are documented here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/). This project intends to follow [Semantic Versioning](https://semver.org/spec/v2.0.0.html); no version has been released yet.

## [Unreleased]

- `show` takes two filters, so a reader can ask for one reservation or one machine instead of the whole board. `--reservation-id` narrows the phase records to that reservation, and repeats for more than one; `--machine-id` narrows the phase records and the live publication lock to one machine, and drops the `publication` key when the lock belongs to another machine, so a lock this machine does not hold is not reported as its own. An id the board does not hold is absent from the answer rather than an error, spacing around a value is ignored, and an empty identifier is refused before the board is read. ([#132](https://github.com/agentmemoir/argus/pull/132))

- A repair session that outlives its wall time is now named instead of leaving the line silently stopped. The `repair` object takes an optional `repair.stale-after`, in seconds, and 0 means no watch: the launch writes `repair-<id>.start` in the state folder and the session removes it when it ends, so a tick that finds the window alive with that record at or past the limit logs one line naming the id, the age and the limit, and sends one notice per session; nothing is killed. `--self-test` also takes an optional group name, so `python -m argus.gitsync.main --self-test repair` runs the repair step and its scan alone, the bare flag still runs every group, and an unknown name is refused with the accepted group named.

- A repair round now checks the scope it changed before the next attempt is counted. The `repair` object takes two optional keys: `repair.verify` is a command run from `repo-root` after a repair pushes, given the paths that repair changed in `ARGUS_REPAIR_CHANGED`, one per line, and the commit it started from in `ARGUS_REPAIR_BASE`, and `repair.verify-timeout` bounds how long it may run, applied with `timeout`, or with `gtimeout` where `timeout` is not on PATH; with neither on PATH the command runs unbounded and the driver logs one line saying so. A round writes `verify.id`, its own marker, beside `verify.paths` and `verify.command` before it pushes, and `verify.log` and `verify.rc` after the command runs; an answer whose `verify.id` names another round is ignored, a marker with no `verify.rc` yet reads as running, and a push that fails or pushes nothing clears those five files, so that round is counted as before. A round is a folder named `<pr>-<round>`, and the budget counts attempts: the task header names both numbers, as in `Attempt: 2 of 3 (round 5)`. A round whose own scope fails does not spend an attempt, so the budget stays open for the failure the round was given; the driver logs it as a self-introduced regression, the next task carries the check's output and the paths it covered, and the number of rounds is capped at twice `repair.attempts`, so a repair that keeps regressing still ends in `EXHAUSTED`.

- The driver self-test owns its tmux server: it drops `TMUX` and `TMUX_PANE` before any tmux command, and the leftover sweep unsets them as well, because tmux prefers the server named in `TMUX` over the socket directory it is pointed at. Run from inside a terminal's tmux, the suite used to list and kill sessions on that terminal's server, and the sweep's `kill-server` path ended it, taking every session on it down.

- The driver self-test bounds git discovery at its fixture tree, so a fixture that has lost its own repository refuses instead of walking up into the checkout under test; the fault harness bounds its scratch space the same way. Two cases pin it without assuming a layout: `git_ceiling` proves anything is there to walk to (the path resolves upward with the ceiling off), asserts the refusal, and starts a throwaway tmux session from its environment to check the server's global environment, which the tick's panes inherit; `lost_repo` re-runs the original trigger end to end — a fixture whose `.git` is removed, the real tick in tmux — and asserts the refusal is the first git step's and the enclosing checkout is untouched. Outside that layout the cases say they skipped instead of claiming a bound that never bound. ([#116](https://github.com/agentmemoir/argus/issues/116))

- The repair step reads a pull request's code-scanning alerts when a failing check has no workflow run to open. A code-scanning check's link is a scan result, so `gh run view` can read no log for it, and the repair used to stop there with `BLOCKED`. The alerts are now a second kind of evidence: the task carries them in their own section, the whole list is kept beside the task, a long list is cut where the cut can be seen, the read is pinned to the pull request's head, and a read that fails is named for itself instead of reading as an empty alert list.

- The README is now a landing page that links into `docs/` instead of restating it, and the `docs/` set names every configuration key, the package-root program files, and every run mode, including `--merge-check-only` and `abandon`.

- The `verify` workflow sets `permissions: contents: read`, so its jobs run with a read-only `GITHUB_TOKEN` instead of the repository default.

- A pull request signal snapshot and its events name the comment-trust boolean `allowed` instead of `trusted`, and the `Visibility` field, the fetch parameter, and the reply check follow the new name. The old name is also a static-analysis pattern for sensitive data, so it raised a false code-scanning alert on the signal print.

- The `roadmap` work source is now `phases`. A `phases` object names a checkout, a folder inside it, a branch and a remote; Argus commits and pushes its writes under that folder there, on the same fresh-fetch, retry-and-fail-closed transaction the board uses. The public repo-root must use a different Git push/fetch destination from the private board and phases checkouts, which may share one. The old `roadmap-dir` key is replaced by `phases.directory`.

- A self-test run killed with SIGKILL no longer leaves its tmux session, the idle monitor inside it, and its fixture directory behind. The monitor now ends a session the self-test made as soon as the run that owns it is gone, which closes the session's windows with it, and the fixture directory is recovered by the next run: each run records its own pid and the socket directory of the server it starts in `<fixture>/owner`, and the next run stops the sessions whose name ends in that pid, stops the server whose socket sits inside the fixture, and removes the fixture. A fixture whose recorded run is still alive is left alone, so two runs on one machine cannot delete each other's; a fixture is left in place rather than removed when tmux cannot be asked whether its sessions are gone; a record that cannot be read is swept on age instead of stopping the whole run; and a fixture with no record keeps the hour-old age rule. A fixture kept on purpose with `SELFTEST_KEEP_TMP=1` drops its record, so the next run no longer reads it as abandoned, and the age rule reclaims it about an hour later. The sweep asks `argus/exec_tempdir.py` which directories a fixture can be in, so it looks in the default temporary directory as well: it named `/tmp` alone before, and on macOS that is not where a fixture goes.

- The sync self-test and the fault harness remove their scratch directories instead of leaving them behind, and every scratch directory now carries the pid of the process that made it, so a run killed before its cleanup is reclaimed by the next run rather than waiting for the hour-old age rule.

- The readiness report's two self-tests run git with a fixed configuration (`GIT_CONFIG_GLOBAL` at `/dev/null` and `GIT_CONFIG_NOSYSTEM=1`), so a host's global `core.hooksPath`, signing key, template, or alias no longer reaches their fixture repositories. A machine-wide hook started its hooks inside every fixture git call, which made `make example-check` and `make install-check` several times slower, and a hook that fails made both self-tests fail for a reason that was not in Argus. A repository-local `core.hooksPath` still wins, which is what the rejected-push check installs, and a real run's git calls keep the machine's configuration.

- Estimate factor: with an `estimate` object in the configuration, a phase that finishes from a fresh start moves its developer harness's factor toward phase hours / (ideal days × 2), at most 20% per phase, and the driver commits and pushes the factor file alone. A resumed run is skipped, a harness with no factor starts from the slowest one, and a failed commit puts the file back.

- `make self-test` and `make guard-faults` refuse to start unless the `CI` variable is set; `ARGUS_ALLOW_LOCAL=1` overrides. `make quick` runs the lint, format, type, line-limit, and prose checks without tests.

- Phase helpers can open a draft after the first commit, stage checkpoint paths, and record one CI read. The driver retries readiness for lone and grouped phases.

- `--merge-check-only` settles phase publication and group readiness without selecting, reserving, or launching work. Halted ticks do the same maintenance once no phase process is active. A tick that records a merge or makes a group ready ends before selecting new work. `--stop` holds its claim for an explicit `--resume` or `--release`; clearing the halt marker alone cannot restart it. A resume keeps the line's halt marker.
- `argus` watches a phase's pull request on each tick: code-scanning alerts and review comments are recorded as they change, and one scoped command replies to or reacts to a recorded review comment.
- `argus` ticks an unattended work queue: select a phase, reserve it on a shared Git board, launch its pipeline in tmux, watch the run, and check publication before the next tick.
- One JSONC configuration file names every path and command; a missing required key stops the tick and names the key.
- Reservation groups: several phases claimed in one board write, run on one branch, and published under one pull request, with the claim renewed while a member runs.
- Halt markers on blocked or failed runs, claim cooldown and expiry handling, and a remedy escalation that records open findings and releases the claim.
- Modes: `--check`, `--dry-run`, `--self-test`, `--stop`, and `--session <NUMBER> <PHASE-FILE>`.
- Checks: the driver self-test, the guard-faults harness, and a wheel that ships the shell driver.
- A publication lock left behind by a publish that died stops blocking after the 30 minute heartbeat window, so claim recovery and other phases' publishes proceed. A fresh lock still blocks both; `release-publication` still frees one early.
- A relative `--repo-root` or `--phases-directory` resolves against the working directory, not the configuration file's folder, so `--root .` from the project root names the project root.
- The tmux idle watcher ends when the process that started it is gone, so one run outside tmux, or after its tmux server died, no longer loops as an orphan.
- A reservation group's pull request is made ready for review only when every member has published and its checks pass; a pull request with failing, running, or unreported checks stays in draft with the reason in the publication output, and the driver readies it on the first tick that finds the checks green.
- Publishing a group member merges the open pull requests that target the group branch when they are ready, from this repository, mergeable, not blocked by a review, and green, so a fix for a bug an earlier member left lands before the next member starts. The new `--mode gate --phase NUMBER` runs the same step by hand.
- Publishing the same head twice posts the member's completion comment once.
- Notices go to the `notify.channel` target as written. The driver put `discord:` in front of it a second time, so a channel written as the sample shows (`discord:<id>`) was never delivered.
- The publication output no longer warns that a group member's branch was cut from the earlier member of the same group.
- Self-healing: with a `repair` object in the configuration, a tick that finds the checks of a pull request it published finished red starts one repair run on that branch, at most `repair.attempts` times per pull request. While the checks of a published pull request are still running, the tick waits up to `repair.wait` seconds before starting other work. A repair run never halts the line. `--mode repair` prints the plan.
- A tick that finds the queue empty now runs the merge check on the pull requests still waiting for review. It used to refuse with "coordination state unavailable" on every tick, because it read the selector's exit code, where 1 means nothing is left to reserve, and the last pull requests of a queue were never recorded as merged. The driver now judges whether the selector printed a state, so a selector that gave none still refuses, and a queue waiting on a decision (`BLOCKED_ON_GATE`) is reported as waiting. The selection asked again after the merge check is judged the same way, so the tick that records the last merged pull request of a queue no longer ends in a refusal.
- A line that repeats from tick to tick (the configuration, a renewed claim, a waiting pull request, the selector's warnings, an empty queue, a halt) is logged when it changes, not on every tick. The log is still touched on each tick.
- Trust settings (`issues.trusted-authors`, `trusted-apps`, `trusted-associations`, `codeowners-file`, `resolve-teams`, `comment-trust`, `untrusted-comments`) load for any `driver.provider` when the `issues` block holds only those keys.
- Bots are trusted only through `issues.trusted-apps`; the default `issues.trusted-associations` is `OWNER`, `MEMBER`, and an author association never admits a bot.
- A reply re-checks the comment author's trust from the fresh read before it posts.
- A corrupt run-folder file refuses cleanly: a snapshot without comments, a malformed writes-log line, or a snapshot bound to another pull request no longer raises.
- The recorded pull request snapshot is bound to its pull request, held under a run-folder lock, and written through a unique temp file.
- The driver log for a pull request signal read that failed names the JSON answer file.
- `commands.reply-check` runs a host command on a draft reply before posting and refuses the reply when the command exits non-zero.
- A repair hold on a failed checks read says the read could not be made and gives its exit code or timeout. It used to say the checks were not finished.
- A checkpoint with nothing staged pushes what the branch already has. It used to run a commit that the pre-commit hooks refused, so the repair push was blocked.
- A repair hold on a failed pull request head read names the read failure. It used to read as no change and start no repair.
- Every gh read returns one `GhRead` (the answer, or `None` and why), so a call site names the reason instead of dropping it.
- Push results report the branch's own status line: `pushed` when the ref moved and `nothing-to-push` when it did not. A checkpoint with nothing staged no longer claims a push the branch never needed, the repair shell logs a push only for `pushed` and `committed-and-pushed`, and the issue run-state and publication pushes report the same way. A publication receipt still records the head an up-to-date push left on the branch. ([#122](https://github.com/agentmemoir/argus/issues/122))
- A repair hold records a per-day count of its reasons under the driver state.
- The self-tests and executable test stubs build their fixtures in a directory the host is proved to run, so a machine whose temporary storage is mounted `noexec` no longer reports a hook or stub CLI as broken when its mode is correct. The board, group, and sync self-tests record a refusal instead of falling back to an unprobed directory; the issue-tick, notify, and issue-driver stubs, and the fault harness's scratch, use the shared probed directory; and `make noexecscan` fails a new test that creates its own temp directory or marks a file executable without that helper.
- A halt is recoverable. The run-end halt writes `runs/.driver/halted.json` beside the marker, and clearing the marker makes the next tick resume the recorded phase at the stage it blocked on, proving or fast-forwarding the ledger pins and renewing the board fence before the launch. `--resume [NUMBER]` does the same while the line stays halted. A resumed run is never archived with `--fresh`. `abandon NUMBER` parks a phase that will not resume, and the approval box no longer closes out a halted phase, so a cleared marker cannot advance the queue past it.
- The halt-resume and abandon paths refuse more bad inputs: a resume cuts the phase branch before it proves the ledger pins, so the proof is taken against the HEAD the launch uses; a `run.json` that is present but damaged is refused by name instead of read as an interrupted run; a resume consumes the halt record only when it names the launched phase and no child rewrote it; `abandon NUMBER` holds the driver lock and refuses while a phase window is running or a recorded pid is alive with no window; and the fresh-reservation reply is parsed with the piped JSON on stdin, so a real board answer reaches the fence.
- A resumed member of a reservation group stays on the group's one branch. The resume path has no selection to read the group from, so it reads the declared group from the member's own phase document before the branch step. Without it the branch step named a branch from the member alone, so the member's receipt was published on a branch the group's joins do not know and a second branch carrying the group's commits was left on the remote. A declaration that cannot be read refuses the resume instead of reading it as "runs alone", the refusal repeats the phases reader's words so it names the document to fix, and it names the way out of the refusal. ([#97](https://github.com/agentmemoir/argus/pull/97))
- The driver header names the cron tick as the reserver of the selected phase, and says that the one-phase `--session` mode starts no reservation and writes no claim. The header had claimed that the server reserves the selected phase for every mode, and a reader who believed it would plan a resume or a cleanup on a fence that `--session` never takes. ([#97](https://github.com/agentmemoir/argus/pull/97))
- The driver no longer silences its own stderr when it drops the lock file descriptor. A redirection on an `exec` command applies to the shell and persists, so the redirection written to hide a bad-fd message sent every later stderr write to `/dev/null`: the stop and release paths lost their error output, and the self-test lost the exit trap's explanation of a tripwire violation, which then read as a bare count. ([#99](https://github.com/agentmemoir/argus/issues/99))
