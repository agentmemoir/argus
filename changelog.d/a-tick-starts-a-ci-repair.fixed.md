A tick starts a CI repair round before new work when a phase pull request that waits on review, or an open pull request on a branch an issue run folder records, has a failed check. A fork pull request with the same branch name as an issue branch is ignored. The round runs `repair.pipeline` in the phase window, inside its own temporary git worktree on the pull request branch, so the main checkout never moves. The session pushes the run's commit to that branch without force and removes the worktree; the next tick removes a worktree a crash left behind. Before a removal, work that was not pushed, a push the remote refused included, is kept on a `refs/argus/repair-backup/<pr>-<time>` ref that a notice names. A round counts before its launch, and after `repair.attempts` rounds a still-red check sends one notice. The round's `glide` gets `ARGUS_CONFIG_FILE`.
